Installation

Requires Python 3.11+ and Node.js 18+.

  1. Clone and enter the repo:

    git clone https://github.com/yourname/spendsift.git
cd spendsift

  2. Create the Python environment:

    uv sync

    No uv? Install with pip install uv, then retry.

  3. Build the frontend:

    cd frontend && npm install && npm run build && cd ..
✓
Verify

Run uv run pytest -q from the repo root. All tests should pass before proceeding.

First Run

./.venv/bin/python -m backend.app

Or scripts/run_app.sh, which builds the frontend when it changed and then starts the backend.

Open http://127.0.0.1:8765. The backend serves both the API and the React frontend from one process.

ℹ
Frontend not built?

If you see a placeholder page, run cd frontend && npm run build then restart.

First-time checklist

  1. Go to Settings → Accounts and confirm the default accounts match your institutions. Add or rename as needed.

  2. Export a statement — HDFC or ICICI CSVs are the simplest starting point.

  3. Open Ledger → Import and upload the file.

  4. Work through the Review Queue for any flagged rows.

  5. Open Ledger → Transactions to confirm everything looks right.

  6. Go to Net Worth → Investments and click Refresh beside "Prices as of" to fetch current NAV prices.

Data Folder

Default location: storage/ in the repo root (created on first start). Override with the SPENDSIFT_STORAGE_DIR environment variable.

storage/
├── journal/             # beancount journal — source of truth (main.beancount + one file per year, investments, prices)
├── snapshots/           # copy of journal/ taken before every write
├── imports/             # uploaded statement files
├── templates/           # import templates (YAML, one per fingerprint)
├── rules/               # learned category rules (learned.yaml), loan terms
├── config/              # benchmarks.yaml, tax/<fy>-inputs.yaml (edit freely)
├── prices/              # NAV history (parquet) and price cache
└── prompts/             # copy-paste categorisation prompts (user-owned)

Pending review batches are held in memory until you commit or discard them.

⚠
Back this directory up

journal/ is your primary record. SpendSift snapshots it before every write, but the snapshots live in the same folder — keep an off-site copy too.

Step-by-step: uploading a statement

  1. Open Ledger → Import in the rail. You'll see a large drop zone.

  2. Drag and drop a CSV file (or click Browse to pick one). SpendSift fingerprints the file to identify the institution and tries to match a saved template.

  3. If the file matches a saved template, you go straight to the review step. If it's a new institution, the Map step walks you through column assignment once.

  4. Confirm the source account (e.g. Assets:Bank:HDFC:Savings) and click Import.

  5. High-confidence rows commit immediately. Low-confidence rows stay in the Review Queue for your attention.

Watched folder

Not available yet: every file currently goes through upload on the Import screen (or /ingest-stmt from Claude Code).

Investment files (Groww)

Groww CSV imports go through an additional Investment Review step — a wallet-flow view showing each buy/refund leg with the running Groww:Cash balance. Review the lot reconstruction before committing.

Ledger file merge

Expand Import from ledger-cli / hledger file on the Import screen to merge a plain-text journal. SpendSift maps ledger account names to SpendSift accounts and deduplicates against the existing journal before writing.

Opening Balances

An opening balance is what an account already held before your first record in SpendSift. Without it, balances and net worth start from zero and come out wrong.

The first-import prompt

The first time you import into an account that has no records, the import asks for its opening balance before you commit. When the statement prints the figure (or a running balance lets SpendSift work it out) the prompt suggests it, shows how it was reached, and proposes a date. You can:

  • Record the suggested opening as shown.
  • Edit the amount, direction or date first, then record it.
  • Started at zero if the account really began empty. You tick to confirm, then press Mark started at zero.
  • Skip and add it later. The import still goes through.

Nothing is written until you tick the confirmation and press the button, whether you record an opening, correct one, or mark or unmark started at zero. A restore point of the journal is taken first, and if the result would not validate, the journal is put back as it was.

Which date is suggested

  • Bank statements: when the statement's first date falls anywhere in April, the suggested opening is 31 March, so the whole financial year is covered. Otherwise it is the day before the first date.
  • Credit cards: the opening is the day before the statement cycle starts. A cycle that covers 1 April counts as the April case.

If your first statement starts later than April, the prompt tells you which earlier statement to import first for a full year. You can still go ahead and record the opening where it falls.

A bank statement that starts partway through April still gets a 31 March opening, but its figure is the balance on the day the statement starts. If you later import the earlier April statement, its rows fall between the two dates and would be counted twice, so the account shows a warning (see below). Correct the opening to the 31 March balance, for example the opening printed on that earlier statement, to clear it.

Settings → Opening balances

This checklist lists every account with its state: opening recorded, started at zero, missing, or not set up. Use it for accounts that have no statement (people, loans, cash, other assets):

  • Add opening for an account without one. The form proposes a date before the account's first record.
  • Started at zero for an account that began empty, and Undo to take the mark back. Both ask you to tick a confirmation first.
  • Correct an opening already recorded. The form shows the current figure, and a correction is refused if the opening changed since you opened it. A zero amount is allowed, and you can keep the opening's current date.
  • Mutual-fund opening lots for funds you held before your order history starts: pick the fund, then enter units, total cost and the date the units were allotted. Importing the full order history is better where you have it.

Adding an opening to an account marked started at zero replaces the mark: the account then shows the opening, and Undo is no longer offered.

Openings dated after earlier activity

Some openings do not cover all of an account's records:

  • An opening dated after the account's first record, such as a mid-year restatement of what a friend owes. The records before it have no opening of their own.
  • An opening taken from a statement, with records imported later that fall between the opening's date and the start of that statement.

The checklist marks these Opening dated after earlier activity, and they are counted in the warnings below. Correct proposes a date before the first record. Moving an opening earlier keeps today's balance the same but changes the balances shown between the old and new dates, so check the amount is right for the earlier date before you confirm.

Warnings

A missing opening never blocks anything, but SpendSift flags it so you do not trust wrong numbers. The same flags cover openings dated after earlier activity:

  • A No opening or Late opening badge on the affected account in Net Worth, Liabilities and Credit Cards.
  • A callout on the Dashboard, Net Worth, Liabilities and the checklist that counts both kinds and links to the checklist. The import lists any other account in the batch whose records an opening does not cover.
  • An Openings line in Doctor that counts accounts with activity not covered by an opening balance.

From /ingest-stmt (Claude Code)

The same prompt appears in chat after staging. The commands behind it:

  • opening-check <batch> shows the prompt for a staged batch.
  • openings [--missing] lists the checklist.
  • commit-opening ACCOUNT --amount --direction --date [--batch] records an opening; commit-opening-correction corrects one; commit-opening-zero ACCOUNT [--undo] marks started at zero.

They write only after you approve in chat.

Review Queue

SpendSift only surfaces rows that need a decision. The review screen uses a code-mirror-based editor showing the beancount entries as they'll be written — you edit inline.

Why a row is flaggedWhat to do
Unknown categoryPick a category; SpendSift learns from this choice
Ambiguous transferConfirm whether this is a same-owner transfer or a real expense
New institution or column layoutWalk through one-time column mapping (Map step)
Low-confidence parseVerify the parsed date and amount in the editor
✓
Corrections improve future imports

Every category you confirm during review trains SpendSift. The same merchant is classified correctly on the next import.

⚠
Snapshot on commit

Clicking Commit first copies the journal to snapshots/<timestamp>/, then writes. If the result does not validate, the snapshot is put back.

Templates

A template captures the column mapping and default account for a specific institution's file format. Once saved, future imports from that institution need no manual steps.

View, rename, or delete templates at Settings → Import Templates. Templates are plain YAML files stored in storage/templates/ — you can inspect and edit them directly if auto-detection picks wrong columns.

# storage/templates/<fingerprint>.yaml (example)
institution: HDFC
default_account: Assets:Checking:HDFC
header_row_index: 0
date_column: Date
date_format: "%d/%m/%Y"
narration_column: Narration
debit_column: Withdrawal Amt.(INR )
credit_column: Deposit Amt.(INR )

Deduplication

You can safely re-import a file. SpendSift fingerprints each transaction by institution, date, amount, and narration — exact duplicates are silently skipped. Near-duplicates surface for manual confirmation.

ℹ
Overlapping date ranges

If two exports cover the same period, SpendSift deduplicates across the overlap. If amounts differ slightly between formats, those rows appear in the review queue.

Dashboard

The home screen: where you stand today. It has no period picker; every figure is as of today's date, shown beside the title. Everything on it is a link to the screen that explains it.

Needs action
A red pill at the top right with a count, shown only when there is something to do. Click it for the list: a card bill overdue or due within 7 days (it notes a payment you already made that the card statement does not show yet), transactions this month that still need a category, card statements expected in the next 3 weeks, and bank accounts with no new entries for more than 14 days. Each item has a button to the place that resolves it (the card, Uncategorized, or Import).
Net worth
The figure, its change over 12 months and this month, and a small 12-month line. Beside it, the breakdown as a sum: Investments (with XIRR and gain) + Bank and cash + Other assets − Liabilities = net worth, adding up exactly. Bank and cash shows months of cover: your balance divided by your average monthly spending over the last 3 complete months. Liabilities shows your EMIs and what the cards owe after payments on their way. Click a line to open Net Worth with that section highlighted. These are the same figures Net Worth shows.
Cash flow
For this month, the FY so far or the last 12 months: money in, spent, invested, net cash flow, savings rate, and where the income went (spent, invested, kept, or taken from savings).
Spending
Your average monthly spending over the last 3, 6 and 12 months, and lifestyle drift (the 3-month average against the 12-month one). Months with no spending are left out; when fewer months count than the window, the tile says "avg over N months". All spending | Without one-offs shows the averages with or without one-time spends. Below, the last 12 months as bars; click a month to open it in Expense.
One-time spends
Spends from the last three months that are not recurring and are at least 3 times the usual amount for their category. Subscriptions, premiums and other monthly, quarterly or yearly payments never count, however large, and refunds never count. Click one to open its month in Expense.

Net Worth

One screen with four tabs at the top. The Liabilities rail entry opens its Liabilities tab.

Overview
As of today, like the Dashboard. Tiles for net worth (with its change this FY and this month), assets, liabilities and your investments' return (XIRR) beside the chosen benchmark. A bar shows what your assets are made of; tax already paid (TDS, advance tax) is listed as not counted, since it settles against tax due. Then one card per group: Investments, Property, Bank & cash and Other assets; Loans & EMIs, Credit cards, People and Other liabilities. Each card shows its total, a few facts and its largest accounts; click it for the detail (the Investments tab, a Liabilities view, or the Ledger filtered to that group). A badge in the header warns when a bank account has had no new entries for more than 14 days.
Investments
Each investment vehicle (mutual funds, stocks, FD, …), opening its own view, and Return by vehicle: invested, value, gain and XIRR against a benchmark. Pick the benchmark from the dropdown at the top right (Nifty 50 by default); Blended compares each vehicle with its own benchmark. Your choice is remembered. FD, PPF, NPS, insurance and property are shown at cost, with no return.
Liabilities
Credit cards, Interest, Repayment and Balance; see Liabilities.
Allocation
How your investments split by vehicle (a donut) and by issuer (ranked bars), at cost.
✓
Benchmark figures are yours to set

Nothing is fetched online. The yearly returns come from config/benchmarks.yaml in your data folder, written with rough starting figures the first time you open Net Worth. Edit the numbers, or add a benchmark, and reload. If the file can't be read, the screen says "Benchmark unavailable" and everything else still works; delete the file to get the defaults back.

ℹ
Old links still work

The former Balance screen is now the Overview tab, and the former Liabilities screens are views under the Liabilities tab.

NAV Prices

SpendSift fetches NAV data from AMFI (the Indian mutual fund association) so holdings are always valued at current NAV. The prices strip ("Prices as of …", with Refresh) appears at the top of the investment views under Net Worth → Investments.

Status indicators

The strip shows one of these states:

  • live — NAVs fetched today from AMFI
  • cached — using a recently fetched local copy
  • offline — fetch failed; showing last known values
  • NAVs not fetched yet — no prices on disk yet; click Refresh

The strip also computes whether prices are stale (older than the last business weekday) and shows the as-of date in amber if so.

Refreshing prices

Click Refresh in the strip. SpendSift does a conditional-GET from AMFI's all-NAV file and updates only what changed.

Price-change windows and backfill

The Mutual funds view shows each fund's price returns over several windows. A dash (—) means no historical NAV for that window yet.

If it says historical data is sparse, click Run backfill. SpendSift fetches per-fund historical NAV from mfapi.in — one fund at a time, with a 200 ms rate limit.

Funds not in AMFI

Closed or merged funds won't appear in the AMFI feed. They're listed in the strip's expandable "N funds not priced" disclosure. Add a price manually via the raw ledger editor.

Cash Flow

Two sub-screens under Cash Flow:

Overview
For the selected period: Income, Expenses, Invested, Saved and the Savings rate; a daily or monthly cash-flow chart, as a heatmap or bars (switches at the top right of the panel, remembered: Both | Income | Expenses, Heatmap | Bars, Linear | Compressed); the Flow diagram of money moving between your accounts, income and spending (Summary | Detailed), with refunds and repayments drawn as loops underneath; and a statement of income and expenses by category with the net. Click a day, month, account or flow to see the transactions behind it. Investment charges count as invested, not as spending.
Overview → Compare FYs
The switch at the top of Overview shows financial years side by side: income and expenses by category, one column per FY, for a span you pick (for example the last 3 FYs). The period control in the header is hidden while comparing; switch back to Overview to return to your period.
Recurring
Automatically detected recurring expenses and subscriptions shown as cards — frequency, next expected date, and average amount — for the month in the header.

Expense

Four sub-screens under Expense:

Overview
Spending for the selected period: net spend, spent before refunds, refunds, and how much went via card, bank or other. A heatmap (one cell per day for up to about three months, one per month for longer periods), categories ranked by amount — hover for the top merchants, click to expand every merchant — and the transaction list. The All / Card / Bank / Other switch filters the whole screen by how you paid.
By Tag
Spend in the selected period grouped by tag. Useful for tracking cross-category groups like #vacation-goa. Tags with a slash nest: #travel/goa and #travel/food roll up under #travel.
Budget
Set a monthly target per category here. The budget screen shows the month's spend vs target with a progress bar.
Uncategorized
Merchants still booked as uncategorized, so you can categorize them.
✓
One period for every overview

The Month | FY | Custom control in the header sets the period for Expense, Income, Cash Flow and Credit Cards at once, and is remembered across visits. Custom takes a From and a To date. Investment charges (stamp duty, broker charges) are not counted as spending; Cash Flow shows them under Invested.

Liabilities

Four views under Net Worth → Liabilities (the Liabilities rail entry opens it):

Credit Cards
One tile per card: the balance, the next statement and due dates, and the card's expiry (with an Expiring soon or Expired badge). When you have paid a bill from your bank but the card statement showing "payment received" is not imported yet, the tile says "paid ₹X on <date> · ₹Y left" and a line above the tiles shows Paid, awaiting card statement and the Net owed (or "in credit" if you paid more than you owed). It clears once that statement is imported. Below the tiles: your card spending for the selected period (pick one card or all), and the card's statement lines.
Interest
Finance charges, late fees, and annual fees detected from statement narrations.
Repayment
Timeline of payments made against each liability. Transfers from your bank account to your card are matched automatically.
Balance
Full double-entry balance sheet for the liabilities section — outstanding balance across all cards and loans, plus the card payments awaiting the statement and the net owed.

Income

Two sub-screens under Income, both following the period in the header:

Overview
Money received in the period: net, received before deductions, and deductions such as TDS. The same chart as Expense, in green (heatmap or bars; a reversal shows red). Sources (salary, interest, …) ranked by amount — hover for the payers, click for the transactions — and the list. The All / Card / Bank / Other switch filters by where the money arrived; Card covers cashback credited to a card.
By Tag
Tagged income in the period, grouped by tag.

Ledger

Three sub-screens under Ledger:

Transactions
The full transaction list — every committed journal entry. Filter by date, account, category, tag, amount, narration, or source file. Click any row to edit category, add tags, or add a note. Changes write back to the journal immediately.
Raw
CodeMirror-based beancount editor for the full journal. Syntax highlighting for dates, narrations, accounts, amounts, comments, and tags. Changes are validated before saving — invalid beancount is rejected with an explanation.
Import
The import surface. Upload a statement file, walk through column mapping, review, and commit. Also the entry point for ledger-cli / hledger journal merges.

Planning

Six calculators under Planning — all local, no data sent anywhere:

Goal Planner
Define financial goals (amount + target year). SpendSift projects whether your current savings rate will reach each goal and shows a funded/short verdict per goal.
SIP Calculator
Given a monthly SIP amount and expected CAGR, projects corpus at maturity with an area chart of invested amount vs total value.
Lumpsum Calculator
Same as SIP but for a one-time investment. Projects future value at a given rate.
CAGR Calculator
Computes CAGR from initial value, final value, and duration. Or reverse: given CAGR and duration, computes final value.
In-Hand Salary
Gross-to-net salary calculator for Indian payroll — PF, income tax (old/new regime), professional tax, HRA. Shows a "tax working" breakdown panel.
FIRE Calculator
Retirement corpus from monthly expense, inflation, years to retirement and a corpus multiple, split across five buckets (safety, cash, low, medium and growth risk).

Tax Workspace

Tax planning is a first-class surface. Everything in the workspace traces back to imported transactions and holdings.

A financial year selector at the top of the Tax rail group lets you switch between FY2023–24, FY2024–25, etc.

Overview
Estimated total tax liability for the selected financial year under old and new regime side by side.
Income
Gross income broken down by source — salary, interest, dividends, rental. Each line traces to the underlying transactions.
Capital Gains
STCG and LTCG from equity and mutual fund disposals, computed using FIFO lot matching. Grouped by asset class with applicable tax rate.
Deductions
80C, 80D, and other declared deductions. User-declared amounts — SpendSift does not auto-detect 80C investments from imports yet.
Regime Compare
Side-by-side old vs new regime with your actual numbers. Shows which regime produces lower tax for your situation.
Prepaid Tax
TDS and advance tax payments found in your transactions, matched against your estimated liability.
⚠
Not tax advice

SpendSift computes estimates from imported data and declared deductions. Consult a CA for filing decisions, especially for complex capital gains, foreign income, or business income.

Quick Add

Record a one-off transaction (cash expense, manual adjustment) without a statement file. Quick Add lives in the rail footer — click the ＋ Quick add button or press n from any screen (when no input has focus).

  1. Press n or click ＋ Quick add in the rail footer. The Quick Add screen opens.

  2. Toggle between Bank (debit/credit) and Investment (buy/sell) at the top of the form.

  3. Enter date, amount, narration, and accounts. SpendSift suggests a category from the narration.

  4. A net-by-account summary panel on the right updates live as you type.

  5. Press ⌘ Enter or click Save. The entry is written to the journal immediately (snapshot first).

ℹ
Same journal, same reports

Quick Add entries appear immediately in all dashboards — they're written identically to imported transactions.

Ledger Journal

Every transaction is stored as a beancount entry under storage/journal/ (main.beancount includes one file per year). This is your primary record — plain-text files you can read, audit, and version-control independently of SpendSift.

What an entry looks like

2025-04-15 * "Swiggy"
  ; source: HDFC_Apr2025.csv | tag: #lunch
  Expenses:Food             450.00 INR
  Assets:Bank:HDFC:Savings

Restoring from snapshot

SpendSift copies journal/ to snapshots/<timestamp>/journal/ before every write. To restore, stop the server, then:

# In storage/ (pick the snapshot to go back to):
rm -r journal && cp -R snapshots/<timestamp>/journal journal

Then restart the server.

Troubleshooting

Import fails with "no template matched"

SpendSift couldn't fingerprint the file. Verify the file is the institution's raw export, unedited. A new institution walks you through one-time column mapping — after that, the template is saved.

Holdings show no value / ₹0

NAV prices haven't been fetched. Open Net Worth → Investments and click Refresh in the prices strip.

Price Returns panel shows all dashes

Historical NAV hasn't been backfilled. If the panel shows a backfill callout, click Run backfill to fetch per-fund history from mfapi.in.

Duplicate transactions after re-import

This shouldn't happen — deduplication is built into every import. If you see duplicates, open Ledger → Raw, find the duplicate by date and amount, and delete the entry. Then file an issue with the CSV so the fingerprinting can be improved.

Journal is corrupt / server won't start

# In storage/:
rm -r journal && cp -R snapshots/<timestamp>/journal journal

Restart the server. If the snapshot is also damaged, restore from your external backup.

Frontend shows a blank page

cd frontend && npm run build

Then restart the server.

Port 8765 is already in use

lsof -i :8765

The app always binds to 127.0.0.1:8765; stop the other process first. (The demo, scripts/run_demo.sh [port], runs on 8766 by default.)
